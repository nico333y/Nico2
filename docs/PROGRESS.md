# وضعیت پیشرفت

- پروژهٔ پایهٔ Android Native با Kotlin و Jetpack Compose ایجاد شد.
- پروژه فقط یک ماژول به نام `app` دارد و از Material 3 استفاده می‌کند.
- صفحهٔ اصلی چت با پس‌زمینهٔ مشکی و ذغالی، رنگ طلایی، وضعیت API و ورودی پیام پیاده‌سازی شد.
- گفتگوها، پیام‌ها و موارد حافظه در فایل JSON نسخه‌دار در فضای خصوصی اپ ذخیره می‌شوند؛ I/O از dispatcher پس‌زمینه انجام می‌شود.
- حالت ناشناس داده‌های همان نشست را از فایل پایدار جدا نگه می‌دارد؛ خاموش‌کردن آن تغییرات ناشناس را دور می‌اندازد.
- جست‌وجو، فیلتر گفتگوها، حذف گفتگو/پیام، سنجاق، مدیریت موارد حافظه و نمایش اندازهٔ واقعی فایل پیاده‌سازی شدند.
- پیام‌های نمونهٔ Demo از داده‌های واقعی جدا هستند؛ گفتگوی متنی پس از پیکربندی کلید از Gemini پاسخ می‌گیرد.
- فایل خراب یا ناسازگار با schema با پیام قابل فهم مدیریت می‌شود؛ سقف اندازهٔ فایل ۴ MiB است.
- پشتیبان‌گیری و انتقال داده‌های خصوصی اپ در manifest و قواعد استخراج غیرفعال شدند.
- تست‌های ذخیره/بازیابی، حذف، سنجاق، جست‌وجو، حالت ناشناس و خرابی فایل اضافه شدند.
- اتصال چت متنی به Gemini API فعال است؛ فهرست مدل‌های دارای `generateContent` با کلید کاربر دریافت می‌شود و فقط برای خطای سهمیهٔ HTTP 429 مدل متنی بعدی امتحان می‌شود.
- فهرست مدل به پنج مدل متنی درخواستی و `gemini-3.8-live` محدود شده است؛ شناسهٔ Live حتی در صورت نبودن `BidiGenerateContent` در متادیتای مدل برای اتصال Live قابل انتخاب است.
- خطای handshake وب‌سوکت Live اکنون در صورت وجود، کد HTTP و شناسهٔ مدل را نشان می‌دهد تا خطای مدل/مجوز از خطای شبکه قابل تفکیک باشد.
- پیام setup برای Live مطابق wire schema رسمی ساخته می‌شود؛ `responseModalities` داخل `generationConfig` قرار دارد و آزمون واحد شکل payload را بررسی می‌کند.
- بررسی APK منتشرشده نشان داد تنظیم Live در نسخهٔ قبلی به‌اشتباه `responseModalities` را در ریشهٔ setup می‌فرستاد؛ آن را به `generationConfig.responseModalities` منتقل کردیم و برای گفتگوی زنده transcription ورودی و خروجی را فعال کردیم. تست رگرسیون شکل wire payload را بررسی می‌کند.
- Live مراحل اتصال و تأیید setup را جدا نشان می‌دهد؛ برای اتصال ۲۵ ثانیه و setup پانزده ثانیه timeout وجود دارد تا صفحه در حالت اتصال نامحدود نماند.
- کلید API با AES-GCM و کلید Android Keystore در فایل رمزگذاری‌شدهٔ فضای خصوصی اپ ذخیره می‌شود؛ کلید در سورس یا log قرار نمی‌گیرد. استفادهٔ مستقیم در اپ برای انتشار عمومی امن نیست.
- Gemini Live از WebSocket، میکروفون و AudioTrack استفاده می‌کند؛ مدل‌های دارای `BidiGenerateContent` فهرست می‌شوند و پس از سهمیهٔ 429 به مدل Live دیگری تلاش می‌شود.
- برای Live مجوز زمان‌اجرای میکروفون لازم است؛ با انتقال اپ به پس‌زمینه ضبط متوقف می‌شود. رونوشت‌های ورودی/خروجی به گفتگوی محلی افزوده می‌شوند.
- اتصال شبکه فقط برای Google Gemini API است. backend، همگام‌سازی ابری، Firebase و Room اضافه نشده‌اند.
- پیوست عکس، PDF و متن تا سقف ۸ MiB برای هر فایل و ۱۲ MiB در هر پیام در فضای خصوصی اپ ذخیره می‌شوند؛ حداکثر ۳ پیوست در هر پیام پذیرفته می‌شود.
- پیوست‌های پیام همراه متن به Gemini ارسال می‌شوند؛ پیام‌های قبلی به‌صورت متن در context هستند و فایل پیوست دوباره ارسال نمی‌شود.
- گرفتن عکس برای پیوست چت با camera intent سیستم انجام می‌شود؛ در صفحهٔ Live، CameraX پیش‌نمایش را نشان می‌دهد و فریم‌های JPEG را حداکثر با نرخ ۱ فریم در ثانیه به Gemini Live می‌فرستد.
- فریم‌های دوربین زنده در JSON یا فایل پیوست ذخیره نمی‌شوند؛ کاربر برای استفاده باید مجوز Camera را بدهد و بداند تصویر به Google فرستاده می‌شود.
- مدل/شخصیت، زبان و صدای Gemini Live، سرعت و زیر و بمی، زبان رابط و کاهش انیمیشن در SharedPreferences ذخیره می‌شوند؛ هیچ API key در تنظیمات عمومی SharedPreferences ذخیره نمی‌شود.
- رابط منابع فارسی، انگلیسی و ترکی کلیدهای متناظر کامل دارد.
- منوی اصلی، تب‌های تنظیمات API/شخصیت/صدا/حافظه و صفحهٔ حافظهٔ نمایشی اضافه شدند.
- صفحهٔ صوتی دارای گوی Canvas است؛ بخش انتقال صوت اکنون به Gemini Live متصل است و از میکروفون/بلندگوی واقعی استفاده می‌کند.
- کنترل کاهش انیمیشن ترجیح کاربر را در SharedPreferences ذخیره می‌کند.
- نسخه‌های build: Gradle `9.8.0`، Android Gradle Plugin `9.4.1` و Android SDK Platform `37.0`.
- build و تست‌های unit محلی/API با موفقیت اجرا شدند: `./gradlew :app:testDebugUnitTest :app:assembleDebug`.
- نسخهٔ تست پس از اصلاح اتصال Live با `versionCode` برابر ۲ و `versionName` برابر 1.0.1 ساخته شد؛ آزمون واقعی Gemini Live همچنان به کلید API و دستگاه Android نیاز دارد.
- نسخهٔ 1.0.2 با `versionCode` برابر ۳ تشخیص صوتی کامل‌تر دارد: علت‌ها به شبکه، کلید/مجوز، سهمیه، مدل، درخواست API، سرور، دستگاه، صوت یا پروتکل تقسیم می‌شوند و مرحله، مدل و جزئیات امن‌شدهٔ سرور در کادر قابل پیمایش نمایش داده می‌شوند.
- اسکرین‌شات نسخهٔ 1.0.2 نشان داد WebSocket به `gemini-3.8-live` باز می‌شود ولی هیچ frameای پس از setup نمی‌رسد؛ علت را نمی‌توان فقط از این نشانه به‌طور قطعی به Google یا VPN نسبت داد. نسخهٔ 1.0.3 این وضعیت را «پاسخی نرسید؛ شبکه/VPN یا سرویس Gemini»، همراه با اندازهٔ صف خروجی، نشان می‌دهد و پیشنهاد امتحان شبکه/VPN دیگر می‌دهد.
- کلید آزمایشی Codespaces با WebSocket خام، هم setup حداقلی و هم setup شامل transcription را آزمایش کرد؛ هر دو `setupComplete` دریافت کردند و فهرست مدل برای این کلید `bidiGenerateContent` را اعلام کرد. ارتباط واقعی با دستگاه Android و مسیر شبکهٔ گوشی همچنان در Codespace قابل آزمون نیست.
- نسخهٔ 1.0.4 کد تشخیصی ثابت را در ابتدای خطا نشان می‌دهد؛ setup بی‌پاسخ کد `LIVE_SETUP_NO_RESPONSE` دارد. کدهای `LIVE_*` متعلق به برنامه‌اند؛ خطاهای HTTP با خود کد HTTP (مانند `HTTP_403`) گزارش می‌شوند.
- بررسی نوع فریم با همان کلید و setup برنامه نشان داد Gemini Live پیام `{"setupComplete":{}}` را به شکل WebSocket باینری (۲۶ بایت) برمی‌گرداند. Listener اندروید پیش از این فقط overload متنی `onMessage` را پیاده کرده بود؛ بنابراین ACK معتبر را بی‌صدا نادیده می‌گرفت و پس از ۱۵ ثانیه timeout می‌داد. نسخهٔ 1.0.5 Listener را اصلاح می‌کند تا UTF-8 JSON را در هر دو overload متنی/باینری بخواند؛ تست برای فریم باینری، UTF-8 نامعتبر، parser، وضعیت handshake، timeout و بسته‌شدن زودهنگام افزوده شد.
- لاگ امن session در تگ `Nico2Live` زمان، شناسهٔ session، مدل/endpoint، نتیجهٔ پذیرش محلی setup، نوع/اندازهٔ فریم‌ها، پاسخ setup، خطا/HTTP و closing/closed را ثبت می‌کند؛ API key، بایت‌های صوت و محتوای فریم JSON ثبت نمی‌شوند. callbackهای session منقضی‌شده در UI نادیده گرفته می‌شوند.
- فایل خروجی: `app/build/outputs/apk/debug/app-debug.apk`.
